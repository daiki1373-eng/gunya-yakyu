## Unity 側で吸収したこと

- 全51枚が金×赤の豪華背景で描かれている（★1 のモブも同じ豪華さ）。既存と同じく、★1〜★3 はキャラだけ切り抜いてレア度別の背景に載せるので、レア度と見た目の逆転は起きない。
- 背景色が金×赤でない絵（fortune-apprentice 紫、soccer 緑、panda 緑、hamster 桃、owl 紺、bodybuilder 橙）も ★1〜★2 なので同様に吸収。
- カードの金枠が絵の中に描き込まれている絵（fox / mochi / rock）も、切り抜きで枠は使わない。
- 切り抜きの失敗（自動切り抜きが背景を拾った、または本体を落とした）を個別に抜き直し: pole / rock / zombie（頭が消えていた） / scarecrow / robovac / tengu / yeti / announcer / daibutsu。scarecrow は体の後ろの風の渦が少し残る（「風まかせ」の設定どおりなので許容）。
- penguin（★4）は主役が絵の下端にあり、一覧用の切り出しで空ばかりになっていたので、切り出し位置を下にずらした。
- 顔の位置（対戦カード・カットイン用）は自動推定し、外れた fox / owl / kappa / rock を手で直した。

## フェーズE: 決めポーズ・横向き走り絵の試作の評価（ojisan）

仕組み: `Batting/PoseCardProto.cs`（既定オフ。`PoseCardProto.Enabled = true` で有効）。絵は `Resources/Presentation/proto_ojisan_*.png`。
- 構え（swing_ready）: 打者が投球を待つ間ずっと。振った瞬間 0.1 秒だけ swing_follow、その後は物理の体（振り抜き・転倒）。
- 投げ終わり（pitch_release）: リリースの 0.12 秒前〜0.4 秒後。
- 横向き走り（run_side）: 守備・走者が横へ走る間。向きで左右反転。
- 確認動画: Recordings/protoE_on3.mp4（試作あり）/ protoE_off.mp4（なし）、走り絵は Recordings/runcard_ojisan.png。

良くなった点
- 構え: いちばん効果が大きい。物理の体は待つ間しゃがみ込んで足を前に投げ出した姿勢になりがちで、見た目が崩れる。構えの絵なら打席に立つ姿がカード絵の質のまま。
- 投げ終わり: 片足を高く上げた躍動感のある絵で、投手らしさがはっきり出る。リリースの瞬間に出すので違和感は少ない。
- 走り: 正面の絵が横へ滑る違和感がなくなる。向きの反転も自然。

問題点
- swing_follow はスイング途中の絵なので「振り切り」としては弱く、0.1 秒しか出していない。振り抜いた後は物理の体に戻るので、絵 → 体の切り替わりが一瞬見える。振り切りの絵が別にあれば、振った後 0.3 秒ほど出せて切り替わりが目立たなくなる。
- 絵は1枚ずつなので、走り絵は脚が動かない（上下に弾ませているだけ）。2〜3コマあると自然。
- 切り替えの瞬間に体が「パッと」入れ替わる（今は即切り替え）。短いフェードで和らげられる。
- 転倒・のけぞりなど物理の見せ場は体のまま（ゲームの核なので残す方針）。

全キャラへ展開する場合の作業量の見立て
- 絵: 1キャラ4枚（構え・振り切り・投げ終わり・横向き走り）× 96体 = 384枚。走りを2コマにすると 480枚。
  投手専任・打者専門は使わない絵があるので、ポジションで絞ると 約300枚。
- こちらの作業: 絵が届けば prep.py で整えて登録するだけ（1キャラ数分）。足元の位置合わせは自動。
- 試作の仕組みは ojisan 以外のキャラにもそのまま使える（ファイル名 proto_<id>_<pose>.png で自動で拾う）。
